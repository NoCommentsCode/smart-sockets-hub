# ⚡ Smart Sockets Hub

Веб-панель для управления умными розетками на базе **ESP32 + MicroPython**.
Собирает все контроллеры в локальной сети, показывает их состояние и даёт
единый интерфейс для управления — с компьютера, планшета или телефона.

**Стек:** FastAPI · SQLAlchemy 2.0 (async) · SQLite · JWT в httpOnly-cookie · bcrypt · ванильный JS

## Возможности

### Управление розетками (доступно всем авторизованным)
- 🔍 **Автопоиск контроллеров** в локальной сети — IP-адреса сохраняются в БД, ничего не нужно вписывать руками
- 🗂 **Группировка по контроллерам**: одна ESP32 = одна карточка со списком своих розеток
- 🟢 **Две секции листинга**: «В сети» сверху, «Не в сети» снизу; устройство перемещается между ними автоматически
- 🔌 Включение/выключение каждой розетки, кнопки «Включить все / Выключить все» на карточке и глобально
- ✏️ **Редактирование контроллера**: имя устройства, имена любых розеток и состояние каждой розетки по умолчанию — сохраняется прямо в конфиг на ESP32
- 🔄 Живое обновление статусов (фоновый опрос + автообновление интерфейса)

### Админ-панель (только роль `admin`)
- 👥 Список пользователей с поиском по логину и фильтром по роли
- ➕ Создание пользователей через модальное окно
- ✏️ Редактирование: логин, пароль, роль, активность
- 🗑 Удаление с подтверждением
- 🛡 Защита от ошибок: нельзя удалить себя и нельзя убрать последнего активного администратора
- 🗑 Удаление контроллеров из БД (для давно неактивных устройств)
- 📡 Ручной запуск сканирования сети

### Профиль (доступно всем)
- Смена собственного логина и пароля с подтверждением текущим паролем

## Как это работает

```
┌──────────┐   JWT-cookie    ┌──────────────────┐   X-API-Key   ┌─────────────┐
│ Браузер  │ ──────────────> │  Smart Sockets   │ ────────────> │ ESP32 #1    │
│ (ПК/тел) │ <────────────── │      Hub         │ <──────────── │ ESP32 #2    │
└──────────┘    JSON API     │  (FastAPI + БД)  │               │ ESP32 #N    │
                             └────────┬─────────┘               └─────────────┘
                                      │
                             ┌────────▼─────────┐
                             │     SQLite       │  пользователи,
                             │  data/hub.db     │  контроллеры, розетки
                             └──────────────────┘
                                      ▲
                     фоновые задачи: discovery + poller
```

**Ключевые принципы:**

1. **Браузер никогда не обращается к ESP32 напрямую.** API-ключ устройств хранится только на сервере — он не утекает в браузер, нет CORS-проблем, все действия проходят через одну точку.
2. **Интерфейс читает кэш из БД**, а не дёргает устройства при каждом открытии страницы. Фоновые задачи держат данные свежими:
   - `discovery` — сканирует сеть каждые `SCAN_INTERVAL_SECONDS` (по умолчанию 5 мин), находит контроллеры и сохраняет их;
   - `poller` — опрашивает статусы каждые `POLL_INTERVAL_SECONDS` (по умолчанию 10 сек);
   - фронтенд перечитывает список каждые 5 секунд.
3. **Роли проверяются на сервере**, а не только скрытием кнопок в интерфейсе.

**Как находится устройство:** сканер пробует TCP-подключение к порту `DEVICE_HTTP_PORT` на всех адресах подсети, затем делает `GET /api/device/info` с API-ключом. Если ответ похож на нашу прошивку — контроллер и его розетки сохраняются в БД. Устройства, не найденные в очередном скане, помечаются offline (poller вернёт их в строй, как только они ответят).

|---|---|
| Python | 3.11+ (проверено на 3.11 и 3.13) |
| ОС | Windows / Linux / macOS / Raspberry Pi OS |

## Настройка (.env)

Файл `.env` создаётся из `.env.example` и **не попадает в git**.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SECRET_KEY` | — | Ключ подписи JWT. **Обязательно смените.** Сгенерировать: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `DEVICE_API_KEY` | — | API-ключ ESP32. Должен **совпадать** с `API_KEY` в `config.py` прошивки |
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/hub.db` | Строка подключения. Для Postgres: `postgresql+asyncpg://...` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `720` | Время жизни сессии (12 часов) |
| `DEVICE_HTTP_PORT` | `80` | HTTP-порт прошивки ESP32 |
| `SCAN_CIDR` | авто | Подсеть для сканирования, напр. `192.168.1.0/24`. Пусто = автоопределение `/24` от основного интерфейса |
| `SCAN_INTERVAL_SECONDS` | `300` | Период автопоиска контроллеров |
| `POLL_INTERVAL_SECONDS` | `10` | Период опроса статусов |
| `ADMIN_USERNAME` | `admin` | Логин первого администратора |
| `ADMIN_PASSWORD` | — | Пароль первого администратора. **Обязательно смените** |

Пример заполненного файла:

```ini
SECRET_KEY=8f3c1a9e5b7d2f4a6c8e0b1d3f5a7c9e2b4d6f8a0c2e4b6d8f0a2c4e6b8d0f1a
DEVICE_API_KEY=my-home-sockets-secret-key
DATABASE_URL=sqlite+aiosqlite:///./data/hub.db
ADMIN_USERNAME=admin
ADMIN_PASSWORD=Str0ng!Passw0rd
SCAN_CIDR=192.168.1.0/24
SCAN_INTERVAL_SECONDS=300
POLL_INTERVAL_SECONDS=10
```

> ⚠️ `ADMIN_USERNAME` / `ADMIN_PASSWORD` используются **только при первом запуске**, когда таблица пользователей пуста. Дальше пароль меняется через интерфейс (Профиль или Админка), а значения в `.env` игнорируются.

## Первый вход

1. Откройте `http://localhost:8000` (или `http://<IP-сервера>:8000` с другого устройства).
2. Войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`.
3. Нажмите **«Профиль»** в шапке и смените пароль.
4. Зайдите в **«Админка»** → создайте учётные записи для домашних с ролью `user`.
5. Дождитесь автопоиска контроллеров (до 5 минут) или нажмите **«Сканировать сеть»**.

## Использование

### Дашборд (`/`)

Карточки контроллеров сгруппированы в две секции:

```
В СЕТИ (2)
┌───────────────────────────┐  ┌───────────────────────────┐
│ ● Кухня        192.168.1.42 ✏️ 🗑 │  │ ● Гостиная    192.168.1.51 ✏️ 🗑 │
│ [Включить все] [Выключить все]│  │ [Включить все] [Выключить все]│
│ ─────────────────────────  │  │ ─────────────────────────  │
│ Чайник          [Включить] │  │ Торшер         [Выключить] │
│ Подсветка      [Выключить] │  │ ТВ              [Включить] │
└───────────────────────────┘  └───────────────────────────┘

НЕ В СЕТИ (1)
┌───────────────────────────┐
│ ● Старая розетка 192.168.1.77 ✏️ 🗑 │   (полупрозрачная, кнопки заблокированы)
└───────────────────────────┘
```

- **Кнопка розетки** — переключает состояние немедленно.
- **«Включить все / Выключить все»** на карточке — все розетки одного контроллера.
- Те же кнопки в шапке — **все розетки всех контроллеров**; если часть устройств недоступна, придёт уведомление со списком.
- **«Обновить»** — принудительный опрос прямо сейчас.
- **«Сканировать сеть»** (админ) — поиск новых контроллеров.
- **✏️ Настройки контроллера** — доступно всем, см. ниже.
- **🗑 Удалить контроллер** (админ) — убирает запись из БД вместе с розетками.

> ℹ️ Если удалить контроллер, который **сейчас в сети**, следующий автоскан найдёт его снова. Удаление рассчитано на давно неактивные устройства.

### Настройки контроллера (✏️)

Открывается модальное окно, данные читаются **с самого устройства**:

- **Имя контроллера** — например, «Кухня» вместо «Smart Sockets ESP32».
- **Для каждой розетки**: название и переключатель **«Включена по умолчанию»**.
- Можно изменить любое подмножество полей — отправятся только изменения.

> 💡 **Состояние по умолчанию** применяется при следующей перезагрузке ESP32 (подача питания, reset). Изменение этой настройки **не переключает розетку сейчас** — редактирование конфига не дёргает питание нагрузки.

Настройки сохраняются в файл `device_config.json` на флеше устройства и переживают перезагрузку и обновление прошивки. Требуется, чтобы контроллер был **в сети**.

### Профиль

Кнопка **«Профиль»** в шапке на любой странице:

- смена логина;
- смена пароля (нужен текущий пароль + повтор нового).

Доступно всем пользователям, включая `user`.

### Админ-панель (`/admin`)

- Список пользователей: аватар, логин, отметка «вы», роль, статус.
- Поиск по логину и фильтр по роли — работают мгновенно.
- **«＋ Добавить пользователя»** — модальное окно создания (логин, пароль, роль, активность).
- **✏️** — редактирование. Пароль можно оставить пустым, чтобы не менять.
- **🗑** — удаление с подтверждением «Да / Нет».

Ограничения (проверяются на сервере):
- логин: 3–64 символа, уникальный;
- пароль: минимум 6 символов (bcrypt ограничен 72 байтами);
- нельзя удалить самого себя;
- нельзя удалить, отключить или разжаловать **последнего активного администратора**.

## API хаба

Полная интерактивная документация: **`/docs`** (Swagger UI) и **`/redoc`**.

Аутентификация: JWT в httpOnly-cookie `access_token` (выдаётся при логине) либо заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/auth/login` | все | Вход, устанавливает cookie |
| `POST` | `/api/auth/logout` | все | Выход |
| `GET` | `/api/auth/me` | авторизованные | Текущий пользователь |
| `PATCH` | `/api/auth/me` | авторизованные | Смена своего логина / пароля |
| `GET` | `/api/controllers` | авторизованные | Список контроллеров с розетками |
| `GET` | `/api/controllers/{id}/config` | авторизованные | Конфиг с устройства |
| `PATCH` | `/api/controllers/{id}/config` | авторизованные | Имя устройства, имена розеток, `default_state` |
| `POST` | `/api/controllers/{id}/all` | авторизованные | Все розетки контроллера вкл/выкл |
| `POST` | `/api/relays/{pk}/state` | авторизованные | Переключить розетку |
| `POST` | `/api/relays/all` | авторизованные | Все розетки всех контроллеров |
| `POST` | `/api/refresh` | авторизованные | Принудительный опрос |
| `POST` | `/api/scan` | **admin** | Сканирование сети |
| `DELETE` | `/api/controllers/{id}` | **admin** | Удалить контроллер из БД |
| `GET` `POST` | `/api/users` | **admin** | Список / создание пользователей |
| `PATCH` `DELETE` | `/api/users/{id}` | **admin** | Изменение / удаление пользователя |

> ⚠️ **Два разных ID розетки.** В `/api/relays/{pk}/state` используется **первичный ключ в БД хаба** (`id` из `GET /api/controllers`), а в конфиге (`relays[].id`) — **локальный ID на устройстве** (`relay_id`). Не путайте их.

### Примеры (curl)

```bash
# Вход, сохраняем cookie
curl -i -c cookies.txt -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Str0ng!Passw0rd"}'

# Список контроллеров
curl -b cookies.txt http://localhost:8000/api/controllers

# Включить розетку (pk = 1 из ответа выше)
curl -b cookies.txt -X POST http://localhost:8000/api/relays/1/state \
  -H "Content-Type: application/json" -d '{"state":true}'

# Переименовать контроллер и две розетки, третьей задать default_state
curl -b cookies.txt -X PATCH http://localhost:8000/api/controllers/1/config \
  -H "Content-Type: application/json" \
  -d '{
        "device_name": "Кухня",
        "relays": [
          {"id": 1, "name": "Чайник"},
          {"id": 2, "name": "Подсветка", "default_state": true}
        ]
      }'
```

## Требования к прошивке ESP32

Хаб работает с любой прошивкой, реализующей следующий контракт (авторизация — заголовок `X-API-Key` или `Authorization: Bearer`):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/device/info` | Идентификация: `name`, `version`, `ip`, `relays_count`, `uptime` |
| `GET` | `/api/device/config` | Чтение конфига: `device_name`, `relays[{id,name,default_state}]` |
| `PATCH` | `/api/device/config` | Частичное обновление имён и `default_state` |
| `GET` | `/api/relays/status` | `{"relays":[{id,name,state,state_text,default_state}]}` |
| `POST` | `/api/relay/{id}/on` · `/off` | Переключение розетки |
| `POST` | `/api/relays/all/on` · `/all/off` | Все розетки устройства |

Важные детали прошивки:

- `API_KEY` в `config.py` устройства **должен совпадать** с `DEVICE_API_KEY` в `.env` хаба.
- Пользовательские имена и `default_state` хранятся в `device_config.json` на флеше (overlay поверх заводского `config.py`), запись атомарная и только при реальных изменениях.
- `default_state` применяется **один раз при загрузке** устройства.
- Имена ограничены 32 символами; кириллица поддерживается (на OLED транслитерируется).
- Ответы отдаются в UTF-8 с корректным `Content-Length` **в байтах**.
- ESP32 работает только на 2.4 ГГц; при одинаковом SSID для двух полос можно зафиксировать `WIFI_BSSID` (MAC точки 2.4 ГГц) в конфиге прошивки.

Полный контракт устройства описан в `openapi.yaml` репозитория прошивки — его можно импортировать в Postman или открыть в [editor.swagger.io](https://editor.swagger.io).

## Деплой на Raspberry Pi

```bash
sudo apt update && sudo apt install -y python3-venv git

git clone https://github.com/<your-username>/smart-sockets-hub.git
cd smart-sockets-hub

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env && nano .env

# проверка
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Автозапуск через systemd

`/etc/systemd/system/sockets-hub.service`:

```ini
[Unit]
Description=Smart Sockets Hub
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/home/pi/smart-sockets-hub
ExecStart=/home/pi/smart-sockets-hub/.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now sockets-hub
sudo systemctl status sockets-hub
journalctl -u sockets-hub -f          # логи
```

> `.env` читается из `WorkingDirectory`, отдельно прописывать `EnvironmentFile` не нужно.

### Зафиксируйте IP

Сделайте **DHCP-резервацию** для Pi в роутере (привязка IP к MAC). Иначе после перезагрузки роутера адрес сменится и все устройства потеряют панель.

Узнать IP: `hostname -I`. С iPhone/iPad также работает `http://raspberrypi.local:8000` (mDNS); на Android надёжнее по IP.

## Доступ с телефона и других устройств

Сервер запускается с `--host 0.0.0.0` — он уже слушает все интерфейсы.

1. Узнайте IP машины: `ipconfig` (Windows) / `hostname -I` (Linux/Pi).
2. Откройте порт в брандмауэре, если он включён.
3. На устройстве в той же сети откройте `http://<IP>:8000`.
4. В меню браузера — **«На экран Домой»**, получится иконка как у приложения.

**Windows (PowerShell от администратора):**

```powershell
New-NetFirewallRule -DisplayName "Smart Sockets Hub 8000" -Direction Inbound `
  -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
```

Сетевой профиль должен быть **«Частная»**, не «Общедоступная».

**Linux с ufw:**

```bash
sudo ufw allow 8000/tcp
```

## Решение проблем

### `ImportError: The SQLAlchemy asyncio module requires ... 'greenlet'`

Не установлена опциональная зависимость:

```bash
pip install "sqlalchemy[asyncio]"
```

В `requirements.txt` уже указано `sqlalchemy[asyncio]>=2.0` — просто переустановите зависимости.

### `ImportError: cannot import name 'ArgsKwargs' from 'pydantic_core._pydantic_core'`

Рассинхрон `pydantic` и `pydantic-core`. Обычно возникает, если папку проекта скопировали **вместе с `.venv`** на другую машину или другую версию Python. Виртуальные окружения непереносимы:

```bash
deactivate
rmdir /s /q .venv          # Windows; Linux: rm -rf .venv
python -m venv .venv
.venv\Scripts\activate     # Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
```

### Порт 8000 занят

```powershell
netstat -ano | findstr :8000     # Windows
```
```bash
sudo lsof -i :8000               # Linux
```

Остановите процесс или запустите на другом порту: `--port 8080`.

### Контроллеры не находятся

- Хаб и ESP32 в **одной подсети**? Сравните IP: `192.168.1.x` vs `192.168.2.x` — разные сети.
- Несколько интерфейсов (VPN, VirtualBox, WSL)? Задайте `SCAN_CIDR` явно.
- В роутере не включён **AP isolation** / гостевая сеть?
- Устройство отвечает вручную?
  ```bash
  curl http://192.168.1.42/api/device/info -H "X-API-Key: <ваш ключ>"
  ```
- `DEVICE_API_KEY` совпадает с `API_KEY` прошивки? При несовпадении устройство вернёт `401`, и сканер его проигнорирует.

### Устройство «не в сети», хотя работает

Poller помечает контроллер offline при таймауте (5 сек). Нажмите **«Обновить»**. Если устройство отвечает медленно, увеличьте таймаут в `device_client.py`.

### Настройки контроллера не открываются (503)

Конфиг читается с самого устройства — оно должно быть онлайн. Дождитесь появления в секции «В сети».

### Изменения в интерфейсе не появляются

Браузер кэширует статику. Сделайте **Ctrl+F5** (на телефоне — приватная вкладка или очистка данных сайта). При правках CSS/JS поднимайте версию в HTML: `/static/app.js?v=6`. В консоли печатается маркер версии загруженного скрипта.

### Забыл пароль администратора

Проще всего сбросить БД (потеряются пользователи и список контроллеров, устройства найдутся заново):

```bash
# остановите сервер
rm data/hub.db        # Windows: del data\hub.db
# задайте ADMIN_PASSWORD в .env и запустите снова
```

## Безопасность

- 🔑 **Смените все дефолты** в `.env`: `SECRET_KEY`, `DEVICE_API_KEY`, `ADMIN_PASSWORD`.
- 🚫 **Не пробрасывайте порт 8000 в интернет.** HTTP + JWT-cookie без TLS за пределами LAN небезопасны. Нужен удалённый доступ — используйте **Tailscale** или **WireGuard**.
- 🔒 Cookie: `httpOnly` + `SameSite=Lax` — базовая защита от XSS-кражи токена и CSRF. При работе через HTTPS включите `secure=True` в `app/api/routes/auth.py`.
- 🛡 Все проверки ролей — на сервере (`require_admin`), скрытие кнопок в UI — только удобство.
- 🔐 Пароли хранятся как bcrypt-хеши; в БД нет открытых паролей.
- 🗝 API-ключ устройств живёт только на сервере и никогда не отдаётся в браузер.
- 📁 `.env` и `data/` исключены из git.

## Разработка

```bash
# режим разработки с автоперезагрузкой Python-кода
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

- `--reload` следит только за `.py`. Статика читается с диска при каждом запросе — перезапуск не нужен, достаточно обновить страницу.
- После правок CSS/JS поднимайте `?v=N` в HTML, чтобы обойти кэш.
- Фиксация версий для одинакового окружения на всех машинах:
  ```bash
  pip freeze > requirements.lock
  pip install -r requirements.lock     # на другой машине / на Pi
  ```
